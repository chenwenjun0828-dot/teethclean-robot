# 洁治器姿态查看器：完整牙模范围选择

## 目标与现状

用户希望在现有三个姿态角查看器中显示完整牙模，并通过参数选择显示范围。
当前 `planning.visualization.pose_angles` 使用内置单颗下颌牙冠和洁治器工作端快照，页面通过 Three.js 渲染，Python 仅负责静态服务。
查看器不求解 IK，不参与碰撞检查，不写回 planning 或 pipeline 的参数文件。

## 建议方案

保留现有单牙模式，增加完整下颌和上下颌模式，同时提供启动参数与页面下拉框。

| 参数值 | 页面名称 | 显示内容 |
| --- | --- | --- |
| `tooth` | 局部牙冠 | 当前单颗牙冠，保持默认行为 |
| `mandibular` | 完整下颌 | 完整下颌口扫模型及当前工具工作端 |
| `both` | 上下颌 | 完整上下颌口扫模型及当前工具工作端 |

启动示例：

```powershell
.\.venv\Scripts\python.exe -m planning.visualization.pose_angles --model-scope mandibular
.\.venv\Scripts\python.exe -m planning.visualization.pose_angles --model-scope both
```

已有 `--port`、`--no-browser` 和双击启动入口继续可用。启动参数指定初始显示范围；运行后可在页面切换，不需要重启服务。

## 数据与坐标

- 从 `assets/source_cad/teeth/mandibular_scan.ply`、`maxillary_scan.ply` 生成适合浏览器展示的简化网格快照，新增资源与当前页面一同保存。
- 使用现有 `models.json` 中的 `contactScanMm` 和 `surfaceFrame`，将完整牙模统一转换到当前局部牙面坐标系，单位仍为 mm。
- 切换范围时 TCP 尖端位置、三个角度和局部坐标轴定义保持一致；工具仍围绕当前示例牙冠的同一参考点转动。
- 完整模式不是选择其他牙齿上的工作点，也不自动改变工具所在牙位。
- 上下颌模式采用原始口扫的相对姿态。本次不新增张口角控制，不读取 pipeline 场景或其张口角。
- 快照在开发时生成，日常启动仍只需要 Python 标准库和浏览器；原始 PLY 更新后不会自动更新快照。

## 页面与交互

- 在现有页面增加“牙模范围”下拉选项，不改动三个角度滑块的数值、范围或数学定义。
- 完整牙模按需加载；加载失败时显示可识别的错误并允许返回局部牙冠模式。
- 切换范围时重新适配相机取景和缩放范围，保证整副模型不会被裁切。
- 保持现有鼠标旋转与缩放，兼顾桌面和手机尺寸；标注不得遮住选择器或滑块。
- 继续使用已有浏览器角度记忆；启动时显式提供的模型范围决定本次初始模式。

## 替代方案与选择理由

另一种方案是在每次启动时读取原始口扫并实时生成网页资源，可及时反映模型修改，但需要运行时网格处理依赖，也会增加启动时间。
本次推荐内置快照，延续现有查看器的数据组织与离线使用方式。

## 实现边界

涉及静态服务入口、姿态查看页面与资源、相关测试和使用文档。
不修改规划、计时、控制或用户当前 pipeline 参数，不将展示网格用于碰撞检查。
