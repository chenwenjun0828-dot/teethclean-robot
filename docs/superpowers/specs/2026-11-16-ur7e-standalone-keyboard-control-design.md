# 独立 UR7e 脚本的键盘启动与停止

- 状态：已批准，实施及离线验收完成；未验证 Linux 真终端与实机
- 问题与目标：当前独立 execute 通过预检后立即发送完整 FollowJointTrajectory。开发者希望启动程序后按 S 开始、空格停止，并确认是否改变轨迹速度。
- 范围：独立运行入口、共享运行器的可选操作事件接口、键盘适配、独立脚本构建、相关测试及模块说明。重新生成 control/employment/2026_11_16/ur7e_saved_trajectory_executor.py；不修改交付 trajectory.json、轨迹时序、速度倍率算法、来源策略或原项目 CLI 的默认行为。

## 设计

1. 独立 execute 增加可选 --keyboard；未指定时保持现有启动方式。inspect/check 不启用运动按键。该开关与 --speed-factor 兼容。
2. 使用 Linux 交互终端单键输入，不要求回车；S/s 请求启动，空格请求停止。只在本终端获得键盘输入时有效，不捕获桌面全局热键。不新增 GUI 或第三方键盘库；非交互终端、重定向输入或不支持的环境明确拒绝 --keyboard，不回退为自动运动。
3. 输入适配只发布线程安全事件；共享运行器仍负责唯一一次轨迹发送、状态监控及停止。键盘线程不调用机器人接口，不在监控循环中使用阻塞 input()，不按键逐点发送。
4. 预检通过后进入等待启动，持续监控首点、静止、力、状态新鲜度与看门狗并维持执行所需心跳。准备好之前的 S 输入丢弃，重复 S 不重复发送。等待耗时不计入运动墙钟超时。
5. 接受 S 后再次检查实时状态、部署授权有效期、原始文件及外层 JSON 指纹，再发送一次完整轨迹；不能以启动脚本时的旧检查覆盖长时间等待。
6. 空格事件锁存且优先于 S。尚未发送时取消本次启动并退出，不发送 goal/cancel/stop；进入发送阶段后，通过原停止流程取消当前 goal、调用现场停止服务并验证关节速度持续低于阈值。对已提出的停止请求禁止自动重发。
7. 停止意味着终止本次执行，不是暂停，不提供原地续跑、重规划或自动返回起点。按 S 不能在停住后重新激活轨迹。再次运行仍必须满足原起点检查。
8. 输入 EOF、监听异常等可检测故障视为取消/停止；Ctrl+C 保留原取消与停稳确认处理。终端关闭或进程被强制结束不能依赖 Python 清理，仍由独立看门狗处理。所有正常退出和异常路径恢复终端设置并关闭监听资源。
9. 报告区分启动前取消、操作者停止、故障及正常完成，记录是否尝试/发送轨迹与停稳确认结果；操作停止不伪报为轨迹执行完成。

## 速度与停止语义

- 键盘仅决定何时发送整条轨迹和何时终止，不改 q、dq、ddq、time_from_start、阶段边界或派生执行曲线哈希。正常运行时速度仍由 --speed-factor 及机器人实际速度缩放决定。
- 监听与事件检查存在少量主机开销，不以此承诺硬实时；轨迹插值和定时仍由控制器执行，不引入每个轨迹点的键盘等待。
- 空格停止会使机器人按实际控制器和停止服务行为减速到零，剩余轨迹不执行。键盘检测、监控周期、网络和机器人制动均有延迟，不承诺零延迟或特定停止距离；软件按键不能代替实体急停。
- 力阈值、跟踪容差、看门狗、停止超时及其他保护保持原值。等待启动同样不能跳过状态与首点检查。

## 选择依据

- 推荐终端单键事件：保持现有两文件迁移，工作站终端/SSH 分配 TTY 时可使用，无 GUI 依赖，容易与现有控制生命周期组合。
- 图形窗口按钮：更适合鼠标操作，但需要显示环境、GUI 生命周期与焦点处理，增加单文件依赖和测试面；本轮不实现。
- 阻塞等待输入或按键逐点发送：会阻塞监控或改变发送时序，不满足当前整轨迹执行契约。

## 实施与验收

1. 添加独立键盘事件适配，将标准库平台导入推迟到实际启用时；生成脚本继续无项目、规划或 GUI 依赖。
2. 为共享运行器添加默认不启用的操作接口，明确预检、等待启动、执行、停止和结束的状态与优先级；原 CLI 不注入该接口。
3. 测试无 S 不发送、准备前 S 无效、一次 S 只发送一次、重复 S 不重发、空格优先、发送前取消零运动指令、执行中停止及停止失败报告。
4. 测试等待期间状态失效/授权过期/文件改变拒绝启动，监听失败及 Ctrl+C 清理、停止后 S 不续跑、非 TTY 拒绝。采用隔离文件、Mock 和注入事件，不连接机器人。
5. 对比相同 --speed-factor 下有无键盘模式的 ROS goal 时间/位置/速度/加速度和执行曲线哈希完全一致；缩放监控仍使用控制器实际进度，力与停止测试继续通过。
6. 运行两个硬件专项测试、根 tests 回归及 git diff --check；在仓库外验证生成脚本隔离运行。Linux TTY 单键输入、真实 UR 停止响应及距离需要工作站现场验证，如本机无法运行则明确记录。
7. 验收后重新生成正式日期目录的脚本，确认 trajectory.json 完全未变，原项目调用行为和前序未提交修改保留。

## 兼容性、风险与回退

- 此功能改变启动与停止控制，属于核心行为；需按本次范围审核，前序速度倍率批准不覆盖该功能。
- --keyboard 默认关闭，已有命令兼容。启用后需保持终端输入可用；焦点丢失不等于能检测到故障，窗口在后台时按空格可能无法到达本进程。
- 该脚本不是硬实时安全组件；停止通道、独立看门狗及实体急停仍按现有现场部署验收。
- 回退只撤销本次键盘模块/接口及生成脚本的变化，保留速度倍率、两文件交付、原轨迹和其他既有修改。
