# 无内嵌轨迹数据的 MoveIt 独立执行脚本

- 状态：已按批准范围实施，离线验收通过；待现场验证
- 问题与目标：开发者要求减少当前独立执行器的大量现场参数，参照旧 `smooth_path_executor_1111_json2real.py`，并明确脚本不要存放大段数据。2026-11-16 本会话已选择“沿用旧 MoveIt 方式：只需脚本和轨迹 JSON，但不再包含当前脚本的 TCP、力阈值和独立看门狗监控”。本方案具体化该选择，替代日期交付使用的完整监控客户端。
- 范围：`control/hardware/` 的独立构建和新增精简 MoveIt 运行模块、相应测试与使用说明，重新生成 `control/employment/2026_11_16/ur7e_saved_trajectory_executor.py`。原 `trajectory.json` 的全部 16006 点及字节不改；原保护执行器、项目 CLI、原始导出包及已有未提交修改保留。

## 调查与选择依据

- 旧程序以 `MoveGroupCommander('manipulator')` 使用已启动的 ROS/MoveIt 环境，末端链为 `tool0`，位姿参考为 `base_link`，将 JSON 重建为 `RobotTrajectory` 后交给 `execute`。它没有提供当前完整客户端所需的力阈值、看门狗、现场授权、规划世界到基座变换等参数，不能声称将这些项全部填成了旧值。
- 旧程序的 `set_max_velocity_scaling_factor(0.1)` 和 `set_max_acceleration_scaling_factor(0.075)` 是规划设置；读取 JSON 后没有相应修改点的时间和导数。因此不能用这两个值代替新脚本的 `--speed-factor`，也不能据其推断六关节绝对速度/加速度限值。
- 旧程序还会移动到硬编码末端位姿，并重新规划到轨迹首点。这些额外运动不属于本次配置复用范围。
- 保留完整监控的替代方案是增加第三个配置/参考文件；开发者已明确选择两文件 MoveIt 简化方式。

## 设计

1. 正式交付仍为同名 `.py` 与 `trajectory.json`。脚本仅含控制实现和少量接口选项，不内嵌逐点 TCP、关节轨迹、阶段列表、审计报告或 `SITE_DEPLOYMENT/PLAIN_REFERENCE` 大对象。JSON 保持仅有 `joint_names/points` 及点的四字段，角度 rad、速度 rad/s、加速度 rad/s²、时间 s。
2. 默认使用旧代码明确给出的 `manipulator`、`base_link`、`tool0`，允许命令行覆盖组和坐标链；关节名从 JSON 与现场组双向核对，不改变关节角、偏置或进行 2*pi 包裹。默认值是接口约定，不宣称现场模型已验证为 UR7e。脚本不需要机器人 IP：连接由工作站已启动的 UR7e 驱动与 MoveIt 负责。
3. 保留 `inspect/check/execute` 的区分和当前 `--trajectory/--out/--speed-factor/--keyboard` 用法。`inspect` 检查 JSON，无设备通信；`check` 初始化 MoveIt 并只读核对组/关节、当前关节状态与首点，不发送运动；`execute` 明确调用执行接口。需要同时启动正确的 UR7e 驱动、机器人描述和 MoveIt move_group，仅启动驱动不够。依赖 ROS 1、moveit_commander 和相应消息包，不依赖本项目或仿真模块。
4. 本次不复制旧硬编码初始位姿或自动规划起点。维持当前“已在 JSON 首点才能发送”的行为；从新鲜关节状态检查位置和静止。起点容差默认 0.01 rad、停止速度阈值默认 0.01 rad/s、状态超时默认 1 s、停止等待默认 5 s、连续停稳时间默认 0.2 s、监听周期默认 0.02 s，作为本方案新增且可由 CLI 覆盖的检查参数，全部要求有限正数；它们不是从旧代码发现的现场实测参数。缺失必要状态时拒绝，不自动额外移动。
5. 保留速度倍率：原速不重定时，非原速按 `t/s`、`dq*s`、`ddq*s²` 缩放，并核验有限值、静止首末点、单调纳秒时钟。复用现有五次插值/保守界基础函数；加速仍核对现场 MoveIt/机器人模型提供的六关节速度与加速度上限，缺失时只需补充相应限值，不能把旧 0.1/0.075 当成绝对上限。无法确定有效上限时拒绝加速，不取消原有加速检查。
6. `execute --keyboard` 保持 Linux 前台终端 S/s 开始、空格终止且不续跑。复用现有终端监听组件。执行通过 MoveIt；监听不阻塞在无法响应按键的同步调用中。空格和 Ctrl+C 调用 MoveIt 停止/取消路径，并根据有效关节速度确认停稳；确认失败明确记录，不能只凭 stop 返回或工作线程结束宣称停稳。停止后不返回、不重新规划、不自动重试。缺少可验证的停止接口时在发送前拒绝。
7. 保留轻量输入完整性：脚本可保存一个预期 JSON SHA256 字符串作为配对校验，该字符串不是轨迹数据。执行前及等待 S 后校验文件未改变。原来源状态只在构建时验证和记录，不伪造运行时快照检查；几何回放仍需构建时显式 `--allow-geometry-only`，不能将其标为完整避碰或动力学验证通过。
8. 明确执行能力变化：精简版不包含当前客户端的 TCP 世界坐标跟踪、分阶段力/力矩超限停止、独立看门狗心跳及完整现场证据/授权字段门槛。保留基础输入、起点、执行结果、操作员停止与停稳核对。MoveIt 和机器人自身的保护由现场环境提供；不把它们冒称为原独立监控。不是恒力控制，也没有完成固定牙模接触验收。
9. 精简实现维护在硬件模块，构建器按显式 MoveIt 后端选项生成单脚本；原 portable/plain 保护后端缺省不变。优先复用终端、哈希、消息和插值基础能力，避免复制完整保护运行器或保持手工修改的第二份脚本。生成脚本不携带无关的旧完整运行器与大配置区。

## 兼容性与风险

- 日期目录内脚本从完整保护客户端切换为精简 MoveIt 客户端，依赖和保护能力发生实际变化，旧方案批准不自动覆盖本次切换。
- 现有 JSON 文件、全部轨迹点、原项目 full 执行门槛均不改变。原保护后端仍可用构建器生成到新的输出目录。
- 参考工程 README 明确主要针对 UR3e，不能据同名关节、manipulator 或 tool0 推断 UR7e 型号、TCP 标定及驱动一致；现场应启动匹配 UR7e 的描述和 MoveIt 控制配置。
- 不填写虚构的 IP、限值、审核人或标定数据，不通过预填 true 声称已有原监控能力。未进行 ROS/UR7e 现场验证的部分如实标记。
