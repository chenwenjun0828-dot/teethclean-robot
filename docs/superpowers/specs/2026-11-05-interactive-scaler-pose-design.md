# 牙龈点窗口中的洁治器姿态交互

用户要求在原牙齿坐标系窗口中加载洁治器末端，并可交互调整姿态。继续沿用用户已要求的牙模与视角固定行为。

加载当前 `ur7e_with_tool.xml` 的 `end_scaler_geom`，利用编译后几何与 `scaler_tcp` 的相对变换得到以 TCP 为原点、毫米单位的洁治器网格，避免 STL 原点、单位和 MuJoCo 网格重定位造成偏差。只显示洁治器组件，不加载整条机械臂。

TCP 原点固定在当前牙龈点；相对姿态默认为零，`R_scan_tcp = R_scan_tooth @ Rz(rz) @ Ry(ry) @ Rx(rx)`。三个角度均以度为单位、范围 -180 到 180，使用固定的牙齿局部轴定义，不累积旋转网格。切换牙龈点时保留相对角度。提供滑块与数字输入、姿态归零、模型和 TCP 三轴显示开关、手动适配工具与牙模视图、保存姿态。

牙齿轴仍为金/蓝/红，TCP 轴采用红/绿/蓝并标明 TCP。姿态与点切换只更新动态叠加，保留静态牙模与相机；首次打开或手动视图按钮才重设相机。局部裁剪保持已有显式更新约定。

`--view` 默认加载工具，`--no-tool` 可只显示牙龈点；`--tool-rpy-deg RX RY RZ` 可设置初始相对角度。保存按钮在 `--out` 目录输出相对旋转、角度约定、选中原始点及口扫坐标 TCP 变换，明确标记为预览。该交互不写入规划参数，不求 IK，也不驱动机器人。

验证覆盖模型与实际 MuJoCo TCP 的几何一致性、毫米换算、尖端旋转中心、非交换旋转顺序、重复调整不累积误差、切换点保留相对角度、保存内容、滑块/数值同步以及视角固定。用真实 Open3D 窗口执行回调并渲染证据图，检查控件布局和模型/坐标轴位置；运行已有坐标系与姿态规划回归。

端到端验证发现旧 GLFW 静态预览关闭后，会干扰同一 Windows 进程中的 GUI 布局/渲染事件。交互 `--view` 只导出数据并直接打开窗口；不带 `--view` 时生成静态 PNG。回归覆盖两条分支，避免交互启动依赖旧渲染器。

## 验证记录

`tests.test_scaler_preview`、`tests.test_tooth_frames`、`tests.test_tcp_tooth_alignment` 和 `tests.test_planning_control` 共 29 项通过。独立 STL/XML 变换与 MuJoCo 编译后网格的双向最近点误差小于 0.001 mm。

真实 Open3D 窗口通过完整 `main(... --view)` 启动，执行已注册的滑块、数字框、Next、显示开关、归零、保存和 Fit 回调，断言相机视图及投影矩阵在角度/点变化时保持一致。点 250 切换至 251 后保留 `[25, -20, 35]` 度，保存结果与显示变换一致。窗口自动关闭，报告及三张渲染图位于 `outputs/tooth_frames/scaler_interaction_validation_20261105/`。
