# MoveIt 交付脚本起点容差调整

- 状态：待审核
- 问题与目标：开发者要求把当前起点关节偏差容差从 0.01 rad 改为 0.1 rad（约 5.73°）。当前 `moveit_runtime.py` 的 `start_tolerance_rad` 同时用于起点与终点检查，直接改数值会同时放宽终点完成判断。本方案只放宽起点检查。
- 调查依据：当前默认 `start_tolerance_rad=.01`；`moveit_state_fault` 对传入目标使用该参数。起点预检、等待 S、发送前和 action 成功后的末点核对均调用此函数。工作区含前序未提交改动，本次保留。

## 范围与设计

- 修改 `control/hardware/moveit_runtime.py` 的精简 MoveIt 运行配置和位置目标检查、相关 Mock 测试、硬件说明及日期交付 README；从原构建器重新生成 `control/employment/2026_11_16/ur7e_saved_trajectory_executor.py`。
- 起点默认 `start_tolerance_rad=0.1`，适用于 `check`、`execute` 的预检、等待 S 和发送前检查。任一关节绝对偏差大于 0.1 rad 时拒绝；不做 2*pi 包裹。原 `--start-tolerance-rad` 仍可覆盖。
- 新增独立 `final_tolerance_rad=0.01` / `--final-tolerance-rad`，仅用于执行完成后的末点关节位置核对。实现通过显式传递位置容差区分起点和终点，避免复制状态有效性检查。
- 保持关节速度停稳阈值、状态新鲜度、等待停稳、取消及停止确认逻辑。保持 JSON 的全部点、时间、导数和字节；不增加自动到首点或其他衔接运动。
- 默认值变化只作用于精简 MoveIt 后端，项目原保护执行器不随之修改。

## 选择依据与风险

- 采用起点/终点独立容差：满足本次起点需求，并保持已有末点完成标准。备选为只在命令中设置 0.1，仍会通过共享参数放宽终点且需要每次传参；直接修改共享默认值同样影响终点，两者均不采用。
- 接受起点偏差不代表自动生成从当前姿态到首点的已验证路径。驱动/MoveIt 自身仍可能以各自的起点容差拒绝，或在控制器启动衔接时产生运动；脚本参数不会覆盖现场 MoveIt/控制器配置。本次不修改现场容差或驱动策略，也不宣称 0.1 rad 对应的 TCP 偏移已获得接触验收。
- 兼容性：既有 `--start-tolerance-rad` 继续可用，但以后仅影响起点；此前覆盖该选项同时改变终点的隐式行为移除，需单独用 `--final-tolerance-rad` 配置终点。README 和 CLI 帮助同步说明。
