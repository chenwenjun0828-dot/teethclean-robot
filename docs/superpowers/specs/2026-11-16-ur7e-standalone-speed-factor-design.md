# 独立 UR7e 执行脚本速度倍率

- 状态：已批准，实施及离线验收完成；未验证实机
- 问题与目标：开发者要求给 control/employment/2026_11_16/ 的独立控制脚本增加运动速度选项，例如 2 倍速。当前脚本无速度参数，原轨迹指令时长 124.879636567 s，旧离线导出仅允许 slowdown>=1；本次明确新增独立真机入口的加速能力。
- 范围：control/hardware/standalone_runtime.py、共享运行器必要的可选曲线变换接口、对应生成逻辑、tests/test_standalone_hardware.py 和模块说明；重新生成既有日期交付目录中的控制脚本。若需在交付 JSON 增加尚未提供的限速字段，只增空值，不改原 files 内容、来源标记、授权或已填写的现场参数。保留已有未提交改动。

## 设计与选择

1. 独立 inspect/check/execute 均增加 --speed-factor s，默认 1，要求 s 为有限正数；0.5 为半速，2 为两倍速。只在运动开始前选定，不实现运动中调速。
2. 推荐对整条已保存关节曲线作统一时间缩放：t'=t/s、q'=q、dq'=s*dq、ddq'=s^2*ddq；阶段边界时间同步除以 s，TCP 参考和关节名、首末关节保持不变。以同一变换后的曲线构建 ROS goal、采样跟踪参考、判断阶段和最终完成，避免只改消息时间却监控原参考。
3. 不改文件中的原始轨迹和原哈希。原始数据及授权仍按现有流程验证，变换在内存中进行；记录 speed_factor、原时长、指令时长和派生执行曲线哈希。不得重写报告冒充该速度已经通过原 full 动力学验证。
4. 默认为 1 时保持现有行为和兼容性。当前几何回放策略允许非 1 倍速；full 策略下非 1 倍速会改变原审计时间律，不能继承原 full 的动力学通过结论，先明确拒绝并提示按新时序重新审计/导出。项目原 CLI 不增加加速开关。
5. 加速 s>1 时，deployment.motion_limits 需提供实际可用的六关节 joint_velocity_rad_s 和 joint_acceleration_rad_s2 正数数组，按 joint_names 顺序，单位 rad/s、rad/s^2。不猜测硬件或工具负载对应的允许值。使用现有五次系数和 Bernstein 凸包界对各段的速度、加速度作保守上界核验；超界或缺配置时不发送，并列出失败关节。原速和减速不新增此必填配置。
6. 缩放后重新核对有限数、严格递增的纳秒消息时刻和停止端点；倍率过大造成消息时间退化时拒绝。力、跟踪、状态新鲜度、看门狗和停止阈值不随倍率放宽。状态超时、最大墙钟执行时间和停止超时保持现场配置，不把安全超时整体乘除倍率。
7. ROS speed scaling、示教器速度滑块与保护减速仍由驱动执行。--speed-factor 2 仅代表发送时序为原来的一半，不承诺真实机器人在保护减速下也用一半墙钟时间完成，继续使用控制器实际进度。

备选：调整示教器/驱动全局速度滑块，会影响其他程序且不能据此保证以已保存轨迹两倍速度执行，本次不采用。仅缩短 time_from_start 而保留原 dq/ddq 会改变插值和边界行为，也不采用。

## 预期操作

以下独立脚本接口已实现：

```bash
python3 ur7e_saved_trajectory_executor.py inspect --trajectory trajectory.json --speed-factor 2
python3 ur7e_saved_trajectory_executor.py check --trajectory trajectory.json --speed-factor 2 --out check_2x_001
python3 ur7e_saved_trajectory_executor.py execute --trajectory trajectory.json --speed-factor 2 --out run_2x_001
```

当前源 2 倍速指令时长约 62.439818284 s；原报告的全关节速度/加速度保守最大界约 0.12664 rad/s、0.65189 rad/s^2，缩放后约 0.25329 rad/s、2.60758 rad/s^2。这些是指令曲线界，不是机器人/工具可接受的限值或实机达标证明。

## 实施与验收

1. 添加统一时缩函数和参数校验，复用现有曲线/插值能力，不维护独立的关节插值算法；共享运行器的新增能力默认关闭，原调用方行为不变。
2. 将派生曲线同时用于 ROS 消息和运行监控，保留原来源指纹，生成派生执行摘要及限制检查。
3. 增加测试：1 倍行为一致、2 倍时长减半/速度翻倍/加速度四倍、0.5 倍、阶段和首末点不变；抽样证明 q_s(t)=q(s*t)；验证 ROS goal 与监控曲线相同、缩放实际进度完成。
4. 拒绝 0、负数、NaN/Inf、纳秒退化、缺限速和超限；验证 full 不冒用原动力学审计、原哈希不变、速度选项不影响原项目门槛和停止逻辑。
5. 运行两个硬件专项测试、根 tests 回归、git diff --check；在隔离目录验证生成文件不依赖项目。重新生成正式控制脚本，确认交付 JSON 原 files 内容和全部原始来源文件未变。
6. 不自动连接或驱动实机；Linux ROS、真实跟踪、力和停止距离另需现场验证。当前未配置现场参数，不能据此宣称 2 倍速可接触运行。

## 风险、兼容与回退

- 2 倍速使指令加速度变为 4 倍，加加速度变为 8 倍，负载和接触响应不保证按比例保持；关节运动学限值通过也不等于碰撞、力控或动力学通过。
- 只修改权威源并重新生成交付脚本，不手工修改独立脚本而保留不同的权威实现。原 JSON 来源审计和旧入口继续有效；非 1 倍速使用派生记录。
- 回退仅撤销本次速度功能及其生成脚本变化，恢复默认 1 倍入口；保留前序两文件交付、所有原始轨迹和开发者已有修改。
