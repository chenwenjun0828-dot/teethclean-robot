# 独立执行的明文轨迹点 JSON

- 状态：已批准，实施及离线验收完成
- 问题与目标：开发者要求参照 smooth_path_executor_1111_json2real.py 的 JSON 格式，并明确“只保留轨迹点的信息”。当前日期交付将十份文件 Base64 编码放在 JSON 内，难以直接检查。改为可直接阅读的关节轨迹点文件，继续用一个独立 Python 脚本与一个 JSON 迁移。
- 调查依据：旧脚本的 dict_to_trajectory 读取顶层 joint_names/points；每个点读取 positions、velocities、accelerations、time_from_start。旧脚本还有额外 MoveIt 进场与自动移动，本次只参照数据格式，不将其运动行为接入当前脚本。
- 范围：control/hardware 的独立构建与读取逻辑、共享运行器必要的输入适配、文档和相关契约测试；重新生成 control/employment/2026_11_16/ 的脚本及 trajectory.json。保留当前全部未提交修改。不改规划、原 ROS 导出目录、原项目 CLI、速度算法、键盘和停止策略。

## 数据与设计

1. 新 trajectory.json 顶层仅保留 joint_names 和 points；points 中每个点仅保留 positions、velocities、accelerations、time_from_start。按旧程序的字段名和数组结构输出普通缩进 JSON，不使用 Base64，不包含报告、来源、部署配置或 TCP 数据。
2. 保留完整 16006 点和原始顺序，不裁剪、不抽稀、不重采样，不对关节角取模或换单位，不修改任何 q/dq/ddq/时间数值。关节角 rad、速度 rad/s、加速度 rad/s²、时间 s；joint_names 保留原六关节顺序。原时长仍为 124.879636567 s，倍速继续在执行时由 --speed-factor 决定。
3. 单脚本仍需现场配置、阶段及 TCP 参考才能维持现有监控。将 deployment 集中放在生成脚本中可编辑的配置区；将原来源结论、阶段、逐点 TCP 及必要审计摘要放入脚本内固定参考数据区。参考区为数据，不维护第二套规划/插值算法。JSON 保持纯轨迹点，不新增第三个部署文件。
4. 新脚本将明文点数据与配套固定参考构造成同一执行曲线；严格验证参考点数、顺序、单位、阶段覆盖、起终点停止、有限值及纳秒时钟。缺失或不匹配的参考数据直接拒绝，不猜测 TCP、阶段或来源状态。
5. 对新明文文件建立明确的 SHA256 绑定，运行前及等待 S 后核对；保留原导出文件的哈希与来源状态作为来源记录。构建时仍用原 load_bundle 完整验证原始轨迹、manifest 和快照，再验证新明文点数据与原输入逐项相等。
6. 指纹契约迁移需明确区分：旧版运行时恢复并逐份验证十份原始文件；新版构建时核验原始文件，运行时核验明文轨迹及脚本固定参考的绑定，不再宣称运行时重验没有随行交付的原始快照。脚本/参考数据同样是受信任的交付物，摘要不能替代操作员授权。
7. 原三个来源哈希与已有现场字段保留，不将新文件伪装成旧哈希。现场授权若已填且绑定旧输入，不静默改写审批绑定；应明确指出新格式需要核对的绑定字段。当前交付的未知现场信息仍留空，不填写假 IP、限值、审核人或有效期。
8. 构建入口增加 --format plain（原缺省保持 portable），以便显式生成配套脚本和明文 JSON；旧 ur7e_standalone_v1 文件继续可读。明文输入只由含对应配置/参考数据的配套脚本接收，不能靠任意 joint_names/points 文件绕过来源检查。
9. 保留 --speed-factor 和 execute --keyboard；S 启动、空格终止不续跑、力/状态/跟踪/看门狗检查、加速限值与停止确认均按现有行为执行。geometry_only 独立回放策略保持已有批准范围，不改为完整避碰通过。

## 选择依据与兼容性

- 采用旧程序字段组织，直接打开即可看到关节轨迹，旧 dict_to_trajectory 可以读取其字段。
- 为保留两文件迁移，配置和运行参考放在配套脚本；代价是脚本携带固定数据且要与轨迹一同更新，不能任意混用两次构建的文件。
- 不选择新增 deployment/reference 等伴随文件，避免扩大工作站迁移文件集；不直接丢弃监控参考或忽略来源/指纹。
- 数据读取兼容不代表旧完整程序可用于当前 UR7e 的同等执行验证；其硬编码初始位姿、额外移动与 MoveIt 依赖不在本次迁移范围。

## 风险与回退

- 这是执行输入契约和指纹绑定方式的调整，不能仅修改 JSON 而让现有脚本仍按 Base64 封装解析；必须同时更新配套脚本。
- JSON 变得可读不代表可以任意编辑后执行；修改轨迹数值会导致绑定不匹配，需要重新生成并核验。非 1 倍速仍不冒用原动力学审计。
- 回退时使用保留的原导出目录和现场配置重新生成 portable 格式两文件，不更改规划结果，不保留 _backup 平行源码或删改其他开发者文件。
