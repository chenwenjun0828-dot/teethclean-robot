# 固定牙龈线姿态优化：实施前审查

日期：2026-11-12。

审查对象：`2026-11-12-fixed-line-contact-optimization-design.md`。

状态：完成代码对照、实际模型只读试验和现有测试检查；尚未实现 `contact_opt`。源方案保持原样。

## 1. 结论

固定原线、每节点三个 SO(3) 姿态变量、初始化锁定解析 IK 分支、由姿态派生关节配置、最后独立验收保存节点，这条路线在数学和现有 UR 模型上可以实施。第 9.7 节的隐函数敏感度与世界坐标旋转扰动约定一致。节点验收与连续轨迹验收的边界也已经正确区分。

目前不能直接确认“按草案参数即可完成整个区域的接触优化”。主要缺口是开放口扫网格上的接触距离、碰撞不可行初值的恢复，以及与当前执行型 pipeline 的输出契约。这些需要先完成接触算例和技术验证，不能用优化器成功标志替代。

用户在本轮已确认：**非工作段按部位显式配置最小间隙，先用接触算例校准**。不统一沿用现有 0.15 mm，也不默认为全部 0 mm；尚未确定的部位数值不能由实现静默填写。

## 2. 需要补齐的设计

### P1：接触距离尚缺可以验收的几何定义

对应方案第 6.2、7、9.6 节。

实际上下颌口扫均不是封闭网格。Open3D 的 `compute_signed_distance()` 明确假设网格封闭、内部外部定义明确；不能直接用于当前扫描并把结果当成穿透依据。现有 `CollisionChecker.check()` 在发生网格相交时返回 `-1`，也不能作为穿透深度或梯度。

实施前需要为局部有向间隙定义清楚：

- 法线方向的来源、拓扑一致性以及可信条件。
- 最近点落在面内部、边、顶点、开口边界或多面折叠处时的规则。
- 同一工具工作段存在多处接触时如何完整覆盖，不能仅检查最近的一处。
- 不能只采工具顶点；三角形内部或边的相交也必须被覆盖或明确判为无法验证。
- 优化的局部分离模型与最终原始面片验收如何对应；无效查询不能变成合法接触。

推荐先做局部有向接触后端的验证原型，允许对无法证明侧别的接触输出 `contact_unverifiable`。如果当前网格局部侧别无法建立，再评估增加经过验证的牙体体积几何；不能静默封洞、移动原线或修改牙齿形状。

参考：[Open3D RaycastingScene 距离接口](https://www.open3d.org/docs/0.19.0/python_api/open3d.t.geometry.RaycastingScene.html)。

代码定位：`planning/infrastructure/collision.py:102`，尤其是 `:129` 的相交查询及 `:132` 的失败标记。

### P1：当前参数下，整区几何可行性存在明显风险

对应方案第 3、6、12 节。

在现有前牙区域、三个参考角 `[6.37, 13.26, -0.4]`、零偏移、工作半径 1 mm、姿态最大偏离 5° 下，非工作段与下颌的名义姿态相交较多，详见第 3 节。

即使每个节点都有正规 IK，也不保证固定工作点、有限姿态邻域内存在满足全部接触与非工作段间隙的姿态。优化器必须允许返回“未找到可行解”，并保留全部源节点及违反量。不得把初始化成功等同于接触优化可行。

按部位配置至少应覆盖：工具非工作面片、传感器、安装件、机械臂与牙颌，以及禁止自碰撞对。保存规则及实际生效值。零最小间隙也不等于允许非工作段接触或相交，判定契约应明确写出。

工作段与非工作段的混合边界面片被保守归入非工作段是正确的，但意味着并非 TCP 半径 1 mm 内的所有工具表面都允许接触。当前网格中部分非工作面片的顶点距 TCP 仅约 0.667 mm，需要纳入校准。

### P1：节点产物不能进入现有执行型分发

对应方案第 11、13 节。

当前 `planning.pipeline.run()` 无条件调用 `plan_sweep()` 和轨迹 `validate()`；`pipeline.tracking.run_tracking()` 要求存在轨迹且 `execution_ready=True`，随后访问轨迹时长并执行控制。只增加模式字符串会使正常的节点结果被拒绝或错误地进入轨迹处理。

新模式需要独立分发和节点结果契约：

- 节点全部通过可使用 `status="contact_opt_nodes_verified"`，但始终为 `execution_ready=False`。
- 优化停止原因与独立节点验收结果分别记录；预算耗尽但节点合格也不能虚报优化收敛。
- 不输出 `trajectory.npz`，不调用 TOPPRA、进出场规划、连续路径审计和控制执行。
- CLI 依据节点审查结果返回退出码，不能沿用 `plan is not None` 的轨迹成功规则。
- 对 `execute`、`duration` 及碰撞关闭模式的组合明确拒绝，不生成具有误导性的输出。
- pipeline 的 execution 阶段记录为跳过；节点浏览使用离散姿态选择，不沿用轨迹播放器的隐含插值。

代码定位：`planning/pipeline.py:90`、`:102`；`pipeline/tracking.py:128`、`:140`、`:191`；`planning/__main__.py` 的最终返回规则。

### P2：外层求解器需要选定实际可实现的接口

对应方案第 8、9.6、9.8 节。

草案正确指出 IK 无效试探不能变成 NaN、旧关节或固定大常数，但尚未确定实际子问题后端。`trust-constr` 的普通回调只接收有限数值函数，不能直接返回结构化无效试探。

有两条实施路线：

1. 自己管理接受点、局部线性化、步长和无效试探拒绝，调用现有 ECOS 求解稀疏凸子问题。用弹性变量处理初始碰撞不可行状态，并以真实约束验收最终节点。这与原方案的有效域控制更直接一致，优先做小规模原型验证。
2. 对 `trust-constr` 建立已验证的可评价局部域及数值适配后使用其约束接口。只有适配契约通过测试后才能接入，不能依赖它自动解决分支无解。

两条路线都应对姿态、关节和以米表示的距离约束做显式尺度处理。保留非均匀源参数差分公式，但检查二阶差分带来的条件数，不能只加稀疏标志便认为千变量求解已解决。导数采用节点局部结构，避免全变量乘全节点的差分。

当前环境已安装 ECOS；OSQP、CVXPY 未安装。实际 SciPy 版本为 1.15.3，Open3D 为 0.19.0。

参考：[SciPy 1.15.3 trust-constr](https://docs.scipy.org/doc/scipy-1.15.3/reference/optimize.minimize-trustconstr.html)、[NonlinearConstraint](https://docs.scipy.org/doc/scipy-1.15.3/reference/generated/scipy.optimize.NonlinearConstraint.html)。

### P2：配置示例需要落成单一、可解析的契约

对应方案第 12 节。

示例中的 `ik` 嵌套对象和若干记录字段，不能直接交给当前只认 argparse 参数的 JSON 解析器。建议独立的 `ContactOptConfig` 和 `ContactPolicy`，由 CLI 的一个配置路径加载；模式、固定语义、优化参数和部位间隙分别校验并写入请求。

接触容差仍然必填。0.01 mm 继续只是待校准示例；本轮用户没有确认它作为默认值。IK 位置/角度容差、有限差分尺度、求解预算与停止阈值也需要明确记录。

代码定位：`planning/config.py:7`、`pipeline/parameters.py:parse_parameters`。

### 3.3 参考运动学

924 个参考节点均生成 8 个原始解析候选。本次诊断在候选完整且生成顺序不变的条件下逐个跟踪生成槽位，有 6 个槽位完成连续展开、关节限位和 FK 检查；另外两个直接按最近展开的槽位在首点越界，未尝试替代的合法整数展开，因此不据此断言对应分支不存在。

完成跟踪的序列中，按 0.5 m 特征长度缩放后的雅可比最小奇异值最低约 0.2389，最大相邻关节变化不超过 0.000482 rad；FK 平移误差约为机器数值精度。

这支持“参考运动学初始化具备实现基础”。生产实现仍必须在解析生成处附加稳定标签，不能把本次诊断使用的列表槽位当作持久分支标签。此试验没有检查机械臂节点碰撞。

### 3.4 工具表面相交筛查

对 430 个节点的统一参考姿态，分开查询原始工作/非工作面片与完整上下颌 BVH：

| 下颌查询 | FCL 报告面片相交的节点 | 未相交但距离小于 0.15 mm 的节点 |
| --- | ---: | ---: |
| 工作段 | 366 | 64 |
| 非工作段 | 294 | 117 |

上颌在本次名义工具姿态查询中没有相交，非工作段最小分离距离约 19.69 mm。上述工作段相交数量不能直接转换为超出接触容差的穿透数量，因为这里没有可靠有符号深度。

进一步对每个节点检查中心姿态及 26 个位于 5° SO(3) 边界的方向：

- 187 个节点在这 27 个姿态中没有找到非工作段与下颌无相交的候选。
- 若另要求 0.15 mm 间隙，366 个节点在这些姿态中没有合格候选。
- 第一个未找到无相交候选的节点索引为 84，源参数约 12.0106 mm。

这是有限姿态筛查，**不是连续姿态可行域的穷举，也不是无解证明**；没有联合优化、没有检查工作段接触容差、没有检查机械臂碰撞。它说明当前姿态界与分组/间隙必须经过实际算例验证，不能预先承诺整区一定通过。

## 4. 推荐的实施顺序

1. 接触算例先行：构造明确外侧的平面、封闭曲面、容差内与超容差穿透、多处接触、开口边界、反向法线、边/面内部相交。确定哪些查询可验证，哪些必须拒绝。按部位间隙在这里校准。
2. 实现固定源节点、统一参考朝向、稳定解析标签、合法角度展开、固定分支 IK 和敏感度。该部分不依赖接触后端完成，可以独立开发验证。
3. 接入工作面片分组与节点接触后端，先在当前区域保存逐节点名义诊断，确认负间隙与错误侧处理符合第 1 步算例。
4. 在小规模问题验证稀疏子问题、不可行恢复和 IK 无效步拒绝，再扩到整区密集节点。不能靠缩短源线或删失败节点得到整区成功。
5. 实现保存后重载的独立节点审查、新 CLI/pipeline 分发及离散节点浏览。全部产物保持 `validation_scope="nodes_only"` 和 `execution_ready=False`。

第 1、3 步的几何语义验证是完整优化器的前置条件。可以开始基础实现及校准原型，但在这些条件完成前，不应把草案状态改为“完整接触优化已可用”。
