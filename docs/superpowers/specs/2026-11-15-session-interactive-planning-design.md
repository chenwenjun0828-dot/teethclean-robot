# 真机 Session 可视化选参与规划迭代

- 状态：已批准，已实施并完成仿真验收
- 日期：2026-11-15
- 需求依据：开发者希望先在可视化页面选择三个角度及其他参数，再规划路径，失败后调整并重新规划。
- 本方案假定：页面内可以发起规划，完整机器人回放继续使用现有 `planning.view`；本轮不接通真机。

## 问题与目标

当前 `planning.visualization.pose_angles` 已支持三角度、姿态模式、离面距离和路径位置预览，但只接受普通 `PreparedRegion`，没有完整 session 加载入口。对颌使用默认仿真位置，不能保证与 session 规划的有效坐标解释一致。页面导出的是单点预览 JSON，不能直接作为规划配置或轨迹输入，也没有规划任务与结果反馈。

目标是形成以下可重复操作：加载指定 session -> 调节请求姿态和规划参数 -> 显式发起可达性检查或完整规划 -> 检查结果与实际轨迹 -> 修改参数后新建一轮规划。预览、规划、回放必须使用相同的数据来源和坐标解释。

现有输入检查和起点诊断不等于整条路径可行。本方案不承诺任意参数都存在可行解。

## 范围与方案选择

1. 推荐：扩展现有页面接入 session，并增加单任务规划、结果摘要和实际 TCP 轨迹叠加。复用现有 CLI、规划器和 MuJoCo 回放，能完成开发者提出的迭代流程。
2. 较小方案：页面仅增加 session 和规划配置导出，用户在终端运行与回放。实现更少，但仍需手动切换和管理结果。
3. 本轮不采用：另建完整机器人网页工作站、批量搜索平台或浏览器控制真机，超出当前单区域选参需求。

涉及文件和职责：

- `planning/visualization/pose_angles.py`：预览 session 接入、HTTP 路由和现有入口兼容。
- `planning/visualization/pose_angles_web/`：复用 Three.js 页面，增加规划参数、任务状态和结果显示。
- `planning/visualization/` 中新增职责独立的小模块：管理单个规划子进程、读取结果与生成展示数据，不继续将这些职责堆进预览文件。
- 复用 `planning/session.py`、`perception/session.py`、`planning.config`、现有 planning CLI 与轨迹采样/FK 接口；若必须改变其算法或数据契约，重新审核相关范围。
- 相关说明和可复用回归测试。

不改变原感知曲线、标定资产、区域边界、IK 算法、碰撞策略、时序算法、动力学验收或现有默认配置。不实现接触/恒力控制、真机通信及执行许可变更，不增加依赖。

## 设计

### 1. Session 与场景一致性

查看器增加 `--perception-session`、`--session-camera-frame`、`--jaw`，与 planning 保持输入互斥和参数含义一致。普通 `--perception-result` 与无 session 的既有用法保持兼容。

Session 模式复用 `build_session_simulation` 及 `SessionRegion.with_world_base`，对当前区域、上下颌、有效变换、拍摄关节角采用同一套权威加载链。页面切换区域也复用相同 session 和相机解释，不混用原发布 `PreparedRegion` 的变换与派生光学解释。

Session 与相机解释在启动时确定并在页面只读显示；改变解释需重启或明确重载场景。Session 模式不提供张口角和基座移动控件。依赖缺失的颌或区域显示具体原因并禁止提交，不用默认资产代替。

位置和矩阵计算使用米，展示位置可转为毫米；角度输入为度，关节为弧度，速度为毫米每秒，时间为秒。保留坐标解释未经现场核实的状态及 `robot_execution_allowed=false`。

### 2. 选参与提交

常用参数为三个姿态角、`simple/local_surface/continuous` 模式、正的离面距离、沿线速度、进出场速度；高级参数提供姿态采样间距和既有 `local_angle_search`。默认首轮为非接触，不开放接触容差或安全阈值调整，不强制指定总时长。初值沿用现有有效配置，不宣称其为真机安全参数。

提供“可达性检查”和“完整规划”两个明确命令，分别对应 `check_mode=geometry_only/full`，均设置 `geometry_only=false` 和 `execute=false`。离面零值不在本轮非接触工作流开放。

路径位置滑块只选择预览位置，不改变规划范围；提交始终为当前完整区域。牙面选点属于独立姿态比较，选点状态下禁止发起规划，恢复路径参考后才允许提交。

预览返回的是请求姿态。`simple` 与 `local_surface` 仍允许既有整区和局部有界修正；关闭 `local_angle_search` 仅关闭逐位置搜索，不代表取消整区修正。结果需展示实际修正或提供其已有报告位置，不将请求姿态当成规划结果。

每次提交取得页面完整参数快照，由后端按既有参数/Config 校验。后端限定 session 来源、允许参数和任务类型，拒绝请求中的任意命令、任意输出路径、执行开关或碰撞绕过参数。导出独立的 planning 参数 JSON，不将预览姿态 JSON 伪装为规划配置。

### 3. 任务与产物

本地服务每次只允许一个规划任务。通过参数列表和当前 Python 解释器调用 `python -m planning --params <任务配置>`，工作目录为仓库根目录，不使用 shell 拼接命令。子进程隔离规划的可变 MuJoCo 状态，拖动预览不会影响正在运行的任务。

后端在 `outputs/interactive_planning/<唯一任务名>/` 保存参数快照、日志和任务状态，CLI 产物写入其新建的空 `plan/` 子目录，避免 CLI 非空目录检查失败。来源版本和指纹使用现有 planning 报告，不另造一套来源认证。

页面展示等待、运行、成功、失败和取消状态，读取真实日志与已有阶段信息，不编造百分比。运行时允许调整下一轮预览，但结果始终标注提交时参数；当前参数与结果不同时标为待重新规划。重复点击不能产生并发任务。

取消仅终止本任务的规划子进程，保留诊断产物并标记取消，不视为通过。服务退出时停止自己创建的活动子进程。首次交付不支持脱离服务长期后台运行、恢复任务或多用户任务队列。

HTTP 服务仅绑定回环地址，任务启动和取消使用 POST，校验来源与 JSON 输入；结果读取限定服务创建的任务及其允许文件，防止路径越界。

### 4. 结果、失败与回放

结果摘要读取已有报告，包括模式、状态、轨迹时长、覆盖、碰撞检查、轨迹审计、动力学结果及最小间隙。进程退出码为 0 不能单独形成通过结论。

可达性检查通过只能标为可达性通过，明确碰撞和动力学未验证。完整通过要求现有 `load_verified` 成功，以及 full 模式、审计与动力学报告符合现有执行契约；通过仍仅代表仿真就绪。

仅有轨迹文件的失败目录不能作为成功结果。页面保留错误文本、已有失败阶段、牙位、曲线位置和碰撞对；报告没有定位字段时显示未提供，不猜测位置，也不为定位错误新增碰撞或几何算法。

有可读取轨迹时，使用现有 `Trajectory.sample` 和 `Robot.fk`，在同一 session 场景下采样实际 TCP 路径，用于与请求参考比较。几何可达性结果也可以显示，但必须带相应状态。降低显示采样密度不得影响实际规划和验收。

完整机械臂动画复用已有 `python -m planning.view --plan <任务目录>/plan --paused`，页面提供准确结果目录和可复制回放命令。首轮不新增浏览器机器人播放器，不自动打开控制执行程序。

## 兼容性与主要风险

- 保留原查看器和 planning CLI 用法；新增页面任务属于调用适配，不替代权威规划入口。
- 最大风险是预览与规划变换不一致，需同时比较双颌位置、路径点、法向和请求 TCP 姿态，而非只比较平移。
- 第二类风险是旧成功结果被误认为当前参数结果，必须使用任务参数快照和当前状态区分。
- 规划耗时不确定；失败不自动放宽碰撞、关节连续性、误差或动力学限制。
- 当前上颌区域源依赖缺失，不能承诺上颌规划；可用双颌场景展示不等于上颌区域输入完整。
- 工作区已有大量开发者修改，实施时基于当前状态适配，不能覆盖或回滚已有内容。

## 验证与验收

- 预览、CLI 规划、回放在两种相机解释下使用相同双颌变换；在区域起点、中点、终点验证三个姿态模式的请求 TCP 一致。
- 修改页面每个规划参数后，任务配置与 CLI 请求记录一致；任务运行中继续拖动不能改变该次快照。
- 牙面选点状态、非有限值、缺失区域来源、重复提交、非法来源/路径请求均被拒绝。
- 覆盖 CLI 失败、取消、服务退出、无报告、仅存在部分轨迹、旧结果与当前参数不一致，不出现虚假通过。
- 回归命令沿用 `python -m unittest planning.test_pose_angles tests.test_perception_session tests.test_planning_parameters`；新增可复用任务测试纳入 `planning/test_interactive_planning.py` 并实际运行。
- 使用真实 session 完成一次页面提交到产物读取的可达性流程，再运行完整规划；完整规划没有通过时交付具体失败证据，不宣称已经得到可行轨迹。若需要改变策略或验收条件则重新审核。
- Playwright 检查桌面和窄屏的 Three.js 非空画面、模型位置、控件遮挡、参数快照及状态切换；结合画布像素与截图确认资源正确渲染。
- 最后执行相关下游回归、`git diff --check` 和工作区差异审查。一次性诊断脚本位于仓库外。

## 实施发现：Session 已验证加载修复（补充范围已批准）

- 证据：任务 `outputs/interactive_planning/20261115_135113_8d2f68ca/plan` 完整规划成功，`execution_ready=true`，动力学完成；页面独立调用 `load_verified` 却收到 `Jaw opening override is incompatible with a measured perception session`。
- 原因：`planning/motion_planning/execution.py::load_verified` 先用 `resolve_jaw_opening` 将未传入的 `None` 恢复成报告内的 `0.0`，之后又把恢复值当作显式覆盖拒绝。调用方并未覆盖 session 的实测牙颌位置。
- 建议最小修复：识别 session 来源后，仅对调用方原始传入的非 `None` 张口角拒绝；session 无显式覆盖时复用已有 `rebuild_session_simulation`。普通场景继续恢复保存张口角。保留所有来源、变换、场景、轨迹、碰撞、审计和动力学检查，不改执行许可。
- 范围：仅上述加载逻辑、`planning/visualization/view.py` 中同类保存值向显式参数的转发及相关回归测试；不变更 session 矩阵、真实张口角、安全阈值或报告文件。原产物可重新检查，无需手改报告。
- 验收：默认加载本次完整规划成功；显式提供张口角仍拒绝；来源或场景变化仍拒绝；普通场景已保存张口角回归通过。
- 回退：仅撤回本次修复片段和对应新增测试，保留原产物及其他开发者修改。
- 批准记录：开发者在本会话的补充审核中选择“批准最小修复并完成回归（推荐）”。修复保持默认加载、回放与显式覆盖之间的原定策略。
