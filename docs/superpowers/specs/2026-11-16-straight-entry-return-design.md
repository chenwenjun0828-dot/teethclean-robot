# TCP 直线进场与返回起始姿态

- 状态：已批准，已实施并完成 geometry_only 验收
- 问题与目标：开发者要求替换现有进退场逻辑：从起始位置沿空间直线进入牙龈线起点，沿线结束后从终点沿空间直线返回起始位置。当前 `initial_approach` 优先使用关节直连，必要时偏移进场或关节搜索绕行；`final_retreat` 仅沿末端牙面法向退出 `retreat_mm`（默认 15 mm），还会用关节捷径缩减路点。关节直连或捷径不保证 TCP 直线，退出终点也不是起始位姿。

## 范围与约定

- 替换新生成的区域完整轨迹的默认进场和退场，适用于 `continuous/simple/local_surface` 及现有 full/geometry_only 检查模式。沿线的感知曲线、离面偏置、姿态策略、源线采样、沿线 IK 节点及 TOPPRA 策略保持原职责。
- “起始位置”明确为本次规划开始时 `robot.home` 的 TCP 位姿；返回时不仅恢复 TCP 位置和方向，而且恢复完全相同的六个关节值，不以相同 TCP 的其他 IK 分支替代。session 中对应拍摄关节角，非 session 对应入口初始化的关节角；不新增人工 home、不修改拍摄关节记录。
- “牙龈线起点/终点”是选定并裁剪后的沿线 TCP 轨迹首末位姿，包含现有 `standoff_mm` 偏置。当前例子保留 `0.2 mm` 偏置，不额外移动到原始无偏置源线。
- 直线指 world 坐标（米）下工具 TCP 的位置，关节以 rad、角度报告以度、时间以秒。姿态在两个端点之间沿 SO(3) 最短旋转平滑插值，沿线端点与当前规划角度精确衔接。进场开始/结束、退场开始/结束停止，沿线段内部连续不停顿。
- 保留其他开发者修改。不修改 perception、标定/模型/扫描资产、接触阈值、硬件或控制通信；不修改既有输出。

## 方案选择

1. **采用：笛卡尔直线参考 + 连续 IK + 关节轨迹插值复核。** 复用当前 IK、SciPy 姿态插值和 `Trajectory.sample(t)`/关节多项式契约。在最终插值上验证 TCP 对参考直线和姿态的误差，超差时仅加密进退场采样并重新构建该自由段；不改沿线节点。兼容现有控制和存储，直线精度遵循明确容差。
2. 在线按笛卡尔直线计算 IK：可直接描述严格直线，但需要修改采样/速度加速度、持久化、控制与重计时契约，影响范围更大，本次不采用。
3. 仅连接关节端点或只把显示路径画直：不能保证实际 TCP 路径，本次不采用。

## 设计

1. 生成两段显式参考：`FK(home) -> trace_start`、`trace_end -> FK(home)`。TCP 位置为 `p(u)=(1-u)p0+u*p1`，方向为端点旋转的 Slerp，`u` 从 0 单调到 1；支持同位置异姿态、重复端点等退化情况。不走法向 15 mm 偏移，不启用绕行，不用跨采样点的关节捷径。
2. 优先扩展 `planning/infrastructure/transfer.py` 中已有 `straight_tcp_motion`，避免重复实现直线和姿态插值。连续分支选择必须固定两端关节角，特别是进场精确接上已选沿线首关节、退场精确回到 home；相邻关节变化及旋转约束保持开启。禁止末端突然切换 IK 分支或把关节角按 2*pi 等价值静默改成另一组。
3. 新完整进退场由 `planning/motion_planning/continuous.py` 串接，保持 `transfer -> trace -> retreat` 阶段名和单个 uninterrupted trace。进场/退场所需几何构建与时序复核归 motion planning；低层 IK/变换复用 infrastructure。已有 `search_transfer` 如仍有独立调用或测试则保留为独立能力，但不再作为本默认流程的失败回退。
4. `fixed_path.py` 的自由段当前按相邻关节路点分别生成零速起止的五次多项式。新直线自由段应按整段分配连续的 C2 关节多项式，内部采样点不逐点停车，整段两端速度/加速度归零；复用 SciPy 和现有多项式系数存储，不新增在线 IK 控制器。根据实际插值的速度、加速度和角速度进行时间放大，遵守现有 `transfer_speed_mm_s`、关节及方向限速，不放宽限制。沿线 TOPPRA 不受影响；总时长约束继续包含往返两段。
5. 按既有 `interpolation_position_mm=0.1`、`interpolation_angle_deg=1` 验证进退场实际插值 FK 对完整参考线段及方向的误差，包含区间内部、端点、进度范围和单调性。参考进度及审计采样必须来自实际轨迹，不能只查输入 IK 节点或只测无限长直线。采样验证按有限分辨率明确报告，不宣称解析精确直线或连续碰撞证明。若加密达到显式上限仍超差，则返回包含阶段、位置/方向最大误差的失败原因。
6. full 模式继续检查节点、插值边和最终轨迹上的碰撞/接触与自碰撞；直线被阻挡即失败，不自动绕路，不转成 geometry_only。geometry_only 模式继续明确跳过碰撞与动力学，只用于预览，`execution_ready=false`。沿用本会话当前 geometry_only 设置对指定 session 重建诊断轨迹，不连接真实机器人。
7. 保存初始/终止关节角、TCP 端点、方向插值策略、参考采样/映射和新的进退场策略版本，加入 request/report 和来源指纹。增加进退场几何审计并纳入执行/重计时校验，拒绝版本或参考被篡改的结果。重计时保留已验收的自由段几何，只更改时间律，不把其重新构造成旧的逐点停车曲线。若需单独文件，使用有明确意义的直线进退场参考产物。
8. `Trajectory` 的现有关节数组、阶段名、`sample` 输出及五次系数格式尽量保持兼容；新增参考版本只约束新规划。旧轨迹保持旧路径和保存的执行验证规则，不能加载时变成直线往返或被伪称已通过新直线审计。`retreat_mm` 为历史配置兼容保留，但新直线返回策略不使用该值，并在说明与报告中标明。

## 兼容性与风险

- 新轨迹行为变化会影响所有使用区域规划的入口：返回路径一般比旧 15 mm 退出更长，总时长重新计算；原先依赖绕行才能通过 full 的场景可能因直线不安全而失败。
- TCP 端点可达不保证整条空间直线连续可达；固定两端关节分支也可能不兼容，此时报告不可达/分支不连续，不改变沿线解或关节终点来掩盖失败。零长度异方向和接近 180 度旋转应有确定处理与测试。
- 内部关节多项式可能偏离笛卡尔线，必须用最终实际插值独立验收；不能只增大容差或修改测试预期通过。
- session 仍保留 `robot_execution_allowed=false` 和相机解释限制。geometry_only 成功不代表碰撞、接触、动力学或实机验收通过。
