# 上下颌开合参数设计

用户目标：在 teethclean robot 仿真环境中调整上下颌牙齿之间的张开程度。用户已明确选择牙齿开合；白色椭圆口缘保持独立调节。

## 项目现状

- models/dental_static_component.xml 中 mandibular 与 maxillary 均为 teeth_root 的固定子体，当前共享口扫坐标系。
- 口扫 +X 为左右、+Y 从下颌指向上颌、+Z 朝前方相机。
- 现有 create_simulation 统一加载场景，完整流程将同一 model/data 传给采集、配准和轨迹执行。
- 现有未提交的口缘宽高、前后距离及命令行改动须保留。

## 方案比较与建议

1. 推荐绕后方横轴旋转下颌：角度直观，保留完整牙弓形状，形成由后向前增大的开口；需要提供近似旋转轴。
2. 沿口扫 -Y 平移下颌：毫米偏移直接，但前后牙间距同时变化，只适合作为简化间距调节。

本次建议采用方案 1。口扫不含颞下颌关节，旋转轴是可配置的仿真近似，不宣称为患者真实关节位置。

## 参数与行为

- 新增 config/jaw_opening.json，包含 opening_deg 和 hinge_center_mm。
- opening_deg 默认 0：保持当前口扫安装姿态，并非解剖学完全闭口。正值增大张口，负值相对当前姿态收小。
- 接受 -10 至 40 度的有限数值；此范围为仿真输入边界，不代表生理活动范围或保证无接触。
- 默认 hinge_center_mm 为口扫坐标 [0, 10, -40] 毫米，可按更换后的牙模调整。该值位于当前牙模后方附近，不是从真实关节标定获得。
- 上颌、牙模根体和机器人安装位置保持原值。下颌以绕口扫 +X 的正向旋转实现张大。
- 下颌位姿从加载时的基准位姿计算，多次调整不累加误差。整个牙模刚体移动，纹理和碰撞几何随之更新。
- 不新增机器人自由度，不修改机器人 home/keyframe 的 qpos、ctrl 结构。开口角在完整清洁流程开始前应用，执行期间保持固定。
- 非法角度或旋转轴在修改模型或保存配置前拒绝。保存配置使用临时文件替换。

## 接口与集成

- 新建 pipeline/jaw.py，负责参数验证、配置存取及下颌位姿更新。
- create_simulation 追加可选 jaw_settings 参数：先应用牙模开合，再根据最新牙模位置应用现有口缘配置，最后前向更新。
- 对不含牙模的自定义 MJCF 保持通用加载能力；显式要求开合却找不到所需牙体时报告清晰错误。
- pipeline.run 新增 --jaw-opening-deg，例如 --jaw-opening-deg 15；默认读取保存配置，命令行值仅覆盖本次运行。
- 完整流程报告记录实际角度与旋转轴，并继续使用调整后的同一 model/data 完成采集、配准和执行。
- 新增 python -m pipeline.preview_jaw --opening-deg 15 独立预览，不运行机器人轨迹。支持按键减小/增大角度、复位、显式保存、正视角，以及 --render 导出图片。
- --save 将角度保存为后续 Python 入口默认值。原生 MuJoCo 直接加载 XML 仍显示原始基准姿态。
- 白色口缘尺寸保持独立；若启用到牙模前端的距离定位，每次开合后重新计算该距离所依赖的牙模前端位置。
- 开合后上下颌不再共享同一刚体变换，沿用现有逐颌配准流程和 both 模式保护，不将两颌强行使用同一配准矩阵。

## 验证与交付

- 验证 0 度恢复原始下颌位置，正角度使前牙沿口扫 -Y 移动，上颌及机器人状态不变。
- 验证往返调整不会累积误差、配置保存读取与命令行覆盖一致，非法输入被拒绝。
- 验证下颌网格、相机坐标变换和碰撞几何使用同一更新后位姿。
- 渲染基准及较大开口图，检查旋转方向与显示效果；运行相关已有坐标及口缘回归测试。
- README 补充参数含义、配置位置、预览与完整流程命令，以及 0 度的基准含义。
