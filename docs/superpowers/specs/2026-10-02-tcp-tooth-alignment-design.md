# TCP 与逐点牙齿坐标系对齐

用户已确认本方案并授权修改。默认 offset_mm=0 时，最终轨迹点的 TCP 原点与牙齿坐标系原点一致，TCP 三轴直接采用牙齿三轴：X 牙冠到牙龈、Y 侧向切向、Z 外向法线。不叠加洁治器工作倾角。

规划先选择连续路径、决定执行方向并重采样，再逆变换回口扫毫米坐标，复用 tooth_frames.build_tooth_frames 计算局部姿态，转换到世界米坐标。使用本次配准对应口扫与提取标签，校验口扫哈希。非零偏移沿每点 +Z 施加，保持姿态及点序对应。

TrackingPlan 保存逐点旋转矩阵和目标位姿。逐点 IK 使用上一点关节解，接近及撤离分别使用首尾点的姿态和 +Z 法线；保留关节扫掠碰撞预检和速度约束。控制器继续驱动位置执行器，不修改 TCP 标定或传送仿真机器人。

轨迹点之间沿弧长用 SO(3) Slerp 计算期望姿态用于误差统计；执行仍采用原有的关节插值。导出目标 TCP 和牙齿的世界变换矩阵、逐点 RPY 及关节目标。报告标记 tooth_aligned，按随时间变化的姿态统计误差。

验证覆盖变化姿态 IK、姿态采样、路径反向、世界/口扫单位转换、偏移及首尾法线、非法姿态拒绝、固定姿态兼容性。运行现有相关测试以及完整 MuJoCo 流程，记录位置和姿态误差。仓库目录没有 Git 元数据，因此设计与代码直接保存到当前目录。

## 用户后续授权：跳过大幅姿态变化并完成整段运动

用户要求跳过姿态差别过大的点，并明确选择 45° 阈值。按最后一个保留姿态比较，超阈值的牙齿姿态约束跳过，原始空间路径保留。跳过处沿弧长 Slerp，末尾沿用最后有效姿态，以走到原路径终点。保留点维持精确牙齿对齐，跳过点不再要求三轴重合。

规划增加辅助 IK 执行样本，减少关节插值的 TCP 偏差；原始目标点不变。实际默认路径筛选后完成整段 MuJoCo 运动；报告保留原始目标、实际目标、跳过编号及原因。默认流水线启用筛选，严格模式可关闭筛选，其他 IK/碰撞失败仍停止执行。
